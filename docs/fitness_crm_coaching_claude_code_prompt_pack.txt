FITNESS BUSINESS CRM + COACHING PLATFORM
PROGRESSIVE CLAUDE CODE PROMPT PACK
=================================================

PROJECT GOAL
------------
Build a polished, mobile-first full-stack web application for a fitness business/gym owner.

The application should manage the complete journey:

Lead
 -> CRM follow-up
 -> Conversion
 -> Gym Member / PT Client / Online Coaching Client
 -> Membership management
 -> Coaching management
 -> Workout plans
 -> Diet plans
 -> Weekly check-ins

IMPORTANT MVP BOUNDARIES
------------------------
Build only ONE authenticated internal staff role for now. Do not build trainer, coach, client, member, or other role-based access control yet. The single authenticated user should have access to the whole MVP.

Do NOT build:
- Instagram DM integration
- AI assistant
- Automated Instagram replies
- Actual payment gateway integration
- Client-facing portal
- Progress photo uploads
- Multi-branch support
- Advanced role management

These may be added only in future phases after MVP validation.

PRIMARY PRODUCT REQUIREMENTS
----------------------------
1. Mobile-first web application.
2. Excellent UI/UX. The app should feel lightweight, intuitive and pleasant rather than like a complicated enterprise dashboard.
3. Responsive on mobile, tablet and desktop.
4. One authenticated internal user role for MVP.
5. Configurable branding: gym/business name, logo and primary/accent colors.
6. Email + password authentication.
7. Public lead capture form accessible without login.
8. Manual lead creation inside the app.
9. CRM pipeline:
   New -> Contacted -> Interested -> Follow-up -> Converted -> Lost
10. Convert a lead into:
   - Gym Member
   - PT Client
   - Online Coaching Client
11. Membership management with:
   - Different membership plans
   - Custom start date
   - Custom expiry date
   - Separate gym membership and PT membership
   - Renewal history
   - Manual payment recording only
12. Online coaching management.
13. Workout templates plus client-specific/custom workouts.
14. Exercise library with optional YouTube/external video URLs.
15. Diet plans in Phase 2.
16. Weekly check-ins:
   - Weight
   - Diet adherence, optional
   - Workout adherence, optional
   - Questions
17. No photos for MVP.

RECOMMENDED TECH STACK
----------------------
Use a single repository and a single full-stack application.

- Next.js (latest stable version compatible with the environment)
- TypeScript
- App Router
- Tailwind CSS
- shadcn/ui or similarly high-quality accessible component primitives
- MongoDB Atlas
- Mongoose
- Zod for validation
- React Hook Form where useful
- Email + password authentication using a mature Next.js-compatible auth approach
- bcrypt or another secure password hashing approach
- Server-side route protection
- Server-side authorization checks even though there is one role for now
- Lucide icons
- A clean chart library only where charts genuinely improve UX
- Dockerfile suitable for Render deployment
- Environment variables via .env.local
- .env.example committed without secrets

HOSTING
-------
For this MVP, target:
- Application: Render
- Database: MongoDB Atlas free tier

Do not use Render local disk for persistent application data.

No file storage provider is required for MVP because photos/uploads are out of scope.

PROJECT QUALITY RULES
---------------------
- Strict TypeScript.
- Avoid any unnecessary `any`.
- Keep business logic out of UI components where practical.
- Validate all user input.
- Handle loading, empty, success and error states.
- Prevent duplicate form submissions.
- Use accessible labels and keyboard-friendly controls.
- Use confirmation dialogs for destructive actions.
- Use soft deletion or explicit archival where historical business data should not disappear.
- Preserve historical membership/payment/renewal records.
- Use sensible database indexes.
- Never expose secrets to the browser.
- Never trust client-provided IDs or privileged fields without server-side validation.
- Keep code modular and readable.
- Do not over-engineer microservices. This is one full-stack application.
- Before each major phase, inspect the existing codebase and verify the previous phase.
- Never blindly overwrite working code.
- Run the application/build/tests and fix errors before declaring a phase complete.
- At the end of every phase, provide a concise verification report and list any manual actions still required.

UI/UX DESIGN DIRECTION
----------------------
The design quality is a first-class requirement.

The application should:
- Feel modern, premium and calm.
- Be optimized for one-handed mobile use.
- Use clear visual hierarchy.
- Avoid dense tables on small screens.
- Prefer cards, grouped sections, bottom sheets, drawers and progressive disclosure on mobile where appropriate.
- Use desktop layouts efficiently without making mobile feel like a squeezed desktop dashboard.
- Have clear primary actions.
- Keep forms short and logically grouped.
- Use sensible defaults and inline validation.
- Show contextual empty states with useful calls to action.
- Use clear status badges.
- Use a consistent spacing and typography system.
- Avoid excessive gradients, excessive animations and decorative clutter.
- Avoid making every screen look like a generic admin template.
- Keep the landing page visually strong and conversion-focused.
- Make the public lead form extremely easy to complete on mobile.

Suggested mobile navigation:
- Bottom navigation for the most frequent areas where appropriate.
- Overflow/menu for less frequent sections.
Do not blindly implement this if another navigation pattern is demonstrably more intuitive.
